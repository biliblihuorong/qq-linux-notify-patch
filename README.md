# QQ Linux 通知补丁 (v0.0.2)

修复 QQ Linux 3.2.34 收到新消息不弹系统通知的问题。通过 Electron 启动入口和 preload 观察会话列表，使用系统桌面通知；不修改账号或聊天数据库，不需要机器人或消息转发服务。

适用于 x64 Linux、`/opt/QQ` 安装的 QQ 3.2.34，以及 KDE/GNOME 等标准通知环境。此次运行时修复已在 Arch Linux + KDE Plasma Wayland、QQ `3.2.34-53644` 上验证：后台收到通知，点击后能打开正确会话。其他构建及桌面环境仍需实机验证。

正式发布版本以 GitHub Release 和 `VERSION` 为准；早期源码中的 v6.6 是内部补丁编号。

## 安装

需要 Python 3.9+。先保存 QQ 中未发送的内容，从托盘完全退出 QQ，再执行：

```bash
git clone https://github.com/biliblihuorong/qq-linux-notify-patch.git
cd qq-linux-notify-patch
sudo ./install.sh
```

安装器会核对 QQ 版本、原启动入口、文件权限和运行状态；先备份，再安装三个脚本，最后原子切换 `package.json` 的 `main`。失败时撤回本次入口和脚本。安装完成后以普通用户重新打开 QQ，不要用 sudo 启动 QQ。

若已有旧补丁或安装记录，请先检查并执行下面的 `--restore`，再安装。检测到其他修改时安装器会停止，不会盲目覆盖。

## 卸载与 QQ 更新

完全退出 QQ 后：

```bash
sudo ./install.sh --restore
```

- 新安装记录会校验入口、备份和补丁哈希。另行修改的文件不会被直接移除。
- 兼容旧版 `package.json.pristine` 备份；旧入口与备份不匹配时会拒绝覆盖。
- QQ 更新已经恢复官方入口时，保留新版 `package.json`，不会用旧备份将它降回旧版。
- 原始入口、旧脚本和恢复记录保存在 `/opt/QQ/resources/app/.qq-notify-patch-backups/`，不会随卸载删除。

QQ 升级可能覆盖启动入口，额外脚本可能保留但不再加载。请先检查新版本适配；安装器仅接受 QQ 3.2.34，不自动跨版本打补丁，也不会关闭 QQ 的 sandbox。

## 通知行为

- QQ 在后台或最小化时，未读增长触发通知；免打扰会话不提醒。
- 待发送期间返回 QQ、读掉消息或开启免打扰，会取消排队通知。
- 点击通知会回到原渲染进程中的会话行：优先使用保留的行引用和可用的稳定属性；唯一名称作为后备，同名有歧义时不任意选择。
- 使用 Electron 页面输入事件选择会话，不再假设“会话名称一定是列表第一行文字”。
- 同会话 20 秒最多 1 条；相同内容 45 秒去重；全局每分钟最多 4 条。这些是抑制提醒，不是消息排队。
- 保留原有等待策略：DOM 检查有 250 毫秒节流、800 毫秒后备扫描。预览尚未更新时，约 6 秒用“新消息”兜底；行暂时不可见时最多等约 30 秒。并非每条通知都固定等待 6 秒。

## 隐私与诊断

默认不写诊断文件，也不把会话名、消息预览发送到日志通道。显式启用诊断：

```bash
# 先完全退出当前 QQ，再以普通用户启动。
QQX_DEBUG=1 /opt/QQ/qq
```

技术事件写入 `~/.local/state/qq-notify-patch/status.log`，新文件权限 `0600`，约 64 KiB 后截断。诊断只记录初始化、限流结果和点击路由状态，不记录联系人、群名或消息正文。

仍保留 `QQX_LOG`（自定义诊断路径）和 `QQX_PRELOAD_PATH`（开发用 preload 路径）覆盖；日志文件仅在 `QQX_DEBUG=1` 时写入。

通知本身仍显示会话名和消息预览，并受桌面通知/锁屏设置控制。旧版可能已经产生 `~/.qq-notify-patch.log`；本版本不会读取、清除或继续写入旧日志。

## 已知限制

- 依赖 QQ 的 DOM 结构；腾讯更新 UI 后可能失效。没有覆盖所有会话与消息类型。
- 虚拟列表可视区外的会话可能仅显示“新消息”，离开可视区的会话不一定能定位。
- 会话检测仍有按显示名合并的历史限制；`99+`、红点、同名会话和频繁重排等场景仍需改进。稳定属性缺失时，点击定位也受此限制。
- 最多保留 256 条通知/点击目标的运行时引用；QQ 重启前的旧通知无法依靠新进程恢复其点击目标。
- Wayland 的窗口激活策略和后台渲染会影响显示、点击与时序。不能承诺零延迟。
- 原入口包装只捕获补丁同步加载异常；不是对 QQ 或插件所有异步行为的保证。

## 测试

开发测试使用 Node.js 18+ 与 Python 3.9+，没有第三方依赖，不需要安装 QQ，也不会读写真实 QQ 或用户配置：

```bash
node tests/notifier.cjs
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

测试覆盖待发取消、预览同轮更新、限流/去重、默认不记录聊天内容、点击目标绑定、过期/重放/跨渲染进程拒绝、虚拟行回收、安装失败回退、旧版备份和更新后保留新版入口。真实桌面上的收消息与点击定位仍需要人工验证。

## 文件

| 文件 | 作用 |
|---|---|
| `qq-notifier-main.js` | 通知、集中限流、点击请求验证与 preload 注入 |
| `qq-notifier-preload.js` | 未读检测、待发取消、预览提取与会话行定位 |
| `qq_main_hook.js` | 加载补丁后进入原 QQ 启动链 |
| `install.sh` / `install.py` | 备份、安装、权限/版本校验与安全恢复 |
| `tests/` | 不使用真实 QQ 数据的回归测试 |
